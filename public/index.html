COST & USAGE

SIREN tracks two separate Claude meters. API Tokens are billed to the API key in .env every time an action below runs. Claude Usage measures Claude Code development sessions on this machine — it is not billed per token and no in-app action consumes it.

Claude API Tokens — billed per action

Shown as the API Cost tile in PULSE and the API Usage panel in ENGAGE. Pricing per million tokens: Sonnet 4.6 $3 in / $15 out · Haiku 4.5 $1 in / $5 out.

Every action above is metered server-side as it runs. The PULSE API Cost tile shows the current month (matching the Claude console's “spend this month”) with the all-time total beneath it.

Console Sync — credit balance & monthly spend

The Anthropic API doesn't expose your credit balance, so enter the current values from console.anthropic.com once. SIREN's meter advances both from there: spend counts up, balance counts down. Re-sync any time (e.g. after adding credits).

Claude Usage — development sessions

Shown as the Claude Usage tile in PULSE. It scans local Claude Code session transcripts (~/.claude/projects) and prices the tokens at API-equivalent rates. This measures time spent building SIREN with Claude Code — it is covered by the Claude subscription, not the API key, and nothing you do inside the app adds to it. Each machine shows its own local sessions.

DEV SYNC

SIREN uses Turso — a hosted SQLite database. Both machines point at the same cloud DB via .env. One-time setup below.

Step 1 — Create a Turso database (once)
# Install Turso CLI (Mac/Linux)
brew install tursodatabase/tap/turso

turso auth login
turso db create siren

# Get your credentials
turso db show siren --url
turso db tokens create siren
Step 2 — Add to .env on both machines
TURSO_DATABASE_URL=libsql://siren-yourname.turso.io
TURSO_AUTH_TOKEN=your-token-here
.env is gitignored — add these lines to the existing file on each machine.
Step 3 — Push existing data from this PC (once)
npm run db:push
Copies all rows from the local siren.db to Turso. Only needed once.
Step 4 — Start normally on any machine
npm start
Both machines read and write the same database. No syncing required.
Without Turso configured
Falls back to file:siren.db automatically — local development still works with no setup.
